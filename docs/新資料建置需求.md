## 2026-07-12 兩項優化（兩案皆經使用者確認並已實作）

使用者提出「原本 tagname 對應 item 的設計可沿用，但需要優化」，主控盤點後提兩個具體建議：

### ✅ 提案一：tagname 收斂成單一真相來源（2026-07-12 使用者確認，已實作）
現況 `spec.tagname`（沿用舊系統的欄位）與 `tag_mapping.tagname`（B 棧新的同步驅動表）**兩處都存了 tag 名稱**，但同步 JOB 實際上只認 `tag_mapping`。`spec.tagname` 是舊資料帶過來的裝飾欄位，看起來有效但改了不會生效——將來一定有人踩。
**已執行**：`spec.tagname` 欄位已移除，`tag_mapping` 為唯一權威。tag 名稱在下方主表只填一次（「Tag名稱」欄），載入器據以自動產生同步設定，不需要另外維護一張對應表。
舊系統 tagname 的既有知識不會遺失——Phase C 正式搬遷時會從原始匯出資料產生 tag_mapping 初始列。

### ✅ 提案二：四張表併成一張主表（2026-07-12 使用者確認，已實作）
「廠區清單」與「量測項目清單」的內容**都能從「規格門檻」那張表推導出來**（每列本來就有 plantno 與 item）。
**已執行**（新格式見下方「你要提供的資料表」）：
- **主表一張**：`plantno, item, unit, 類型, LAW, OOS, OOC, Alert, 允收, 來源, tagname, 排序`
  —— 一列 = 一個廠區的一個監測項目，把 tag 對應也併進來，環工部只填一張 Excel。
- **選填小表**：只在需要時填「廠區顯示排序/是否顯示」「項目顯示別名（pH1→pH）」。
- 載入器負責推導廠區/項目主檔、驗證、逐列回報錯誤。
**好處**：不會發生「項目清單有、規格表漏了」這種對不起來的狀況；填寫工作量從四張降為一張。

### 相關：日常維護改走網頁（已在實作）
一次性建置用 Excel 灌，**日常維護（新增廠棟/項目/tag 對應）改用網頁**——「基礎資料維護頁」已於 2026-07-12 發包實作（廠區/項目/Tag 對應三分頁），未來新廠棟上線環工部可自行建置，不必每次找工程師動資料庫。

## 你要提供的資料表

> 2026-07-12 改版：原本四張表（廠區清單／項目清單／規格門檻／Tag 對應）**併成一張主表**。
> 廠區與項目清單本來就能從規格那張推導，分開填反而會發生「項目清單有、規格表漏了」對不起來
> 的狀況。現在只要填 **1 張主表**（＋2 張選填小表），程式會自動推導出所有主檔。

### 主表（必要）— 檔名建議「基礎資料主表」
**一列 = 一個廠區的一個監測項目。** 範本檔：`scripts/templates/基礎資料主表_範本.csv`

| 欄名 | 必填 | 說明 | 範例（單邊） | 範例（雙邊 pH） |
|---|---|---|---|---|
| 廠區代號 | ✓ | 廠區代碼 | K7 | K7 |
| 項目 | ✓ | 監測項目名（唯一；同名不同義請改名，如 VOC(M13)）| COD | pH1 |
| 顯示名 | | 儀表板顯示用，空＝同項目名 | | pH |
| 單位 | | | mg/L | pH |
| 類型 | ✓ | 水質／空汙／雨水溝（影響派報信分類）| 水質 | 水質 |
| 法規值 | | 純顯示文字 | 100 | 6-9 |
| OOS | | 紅燈門檻；**雙邊寫 `低-高`** | 100 | 6-9 |
| OOC | | 橙燈門檻 | 80 | 6.5-8.5 |
| Alert | | 黃燈門檻（最先觸發、範圍最窄）| 60 | 6.8-8.2 |
| 允收值 | | 超過亮黃燈 | 80 | 6.5-8.5 |
| 資料來源 | ✓ | SCADA／CWMS／QA（QA＝人工輸入頁）| SCADA | SCADA |
| Tag名稱 | | 來源＝SCADA 時填，用來產生同步 JOB 的對應設定 | K7.COD.PV | K7.PH.PV |
| 排序 | | 廠區內顯示順序，空＝依填寫順序 | 2 | 1 |

**填寫要點**
- 「尚未建置」的項目：門檻欄留空即可（畫面會顯示建置中）。
- **門檻的層遞關係**：Alert 範圍要包在 OOC 裡、OOC 包在 OOS 裡（Alert 最先觸發）。填錯程式會擋下並告訴你哪一列。
- **pH／溫度這類雙邊項目**：OOS/OOC/Alert 都必須寫成 `低-高`，只寫單一數字會被擋。
- 廠區與項目**不必另外列清單**——程式會從這張表自動推導建檔。

### 選填 1：廠區設定 — 只在需要調整顯示時填
| 欄名 | 說明 |
|---|---|
| 廠區代號 | 對應主表 |
| 顯示排序 | 儀表板由小到大排 |
| 是否顯示 | Y/N（預設 Y）|

不填的話：排序依主表首次出現順序、全部顯示。

### 選填 2：人員與角色 — 沿用既有格式
沿用 `scripts/migration_personnel.json`（empno / name / email 三欄，email 直接寫）：
- 廠棟工程師＝申請人；環工負責人＝簽核人。
- 派送名單（誰收派報信）若要與簽核人不同，另給一張：廠區代號／類別（異常派報或中水通知）／工號／TO 或 CC。不給就預設「簽核人收全部」。

### 其他（都可省略）
- 部門（部門權限頁用）：廠區代號 / 部門代碼。
- 歷史曲線連結：廠區代號 / 項目 / URL。
- **K14B 中水**：中水緊急通知頁固定查 K14B——要用這個功能的話，主表要包含 K14B 的資料。

## 交付方式與載入

CSV（UTF-8）或 Excel（.xlsx，多工作表：主表放第一張或命名為「主表」，廠區設定命名為「廠區設定」）皆可，欄名照上表。

載入指令（`scripts/load_user_data.py`）：
```bash
# 先試跑：只驗證、不寫入，把所有問題一次列出來
python scripts/load_user_data.py --file 你的檔案.xlsx --dry-run

# 確認無誤後真正載入（可重複執行，不會產生重複資料）
python scripts/load_user_data.py --file 你的檔案.xlsx
```
**驗證失敗不會中斷**——程式會把每一列的問題（第幾列、哪個欄位、什麼原因）一次列完，
讓你一輪就改完，不用試一次修一次。
