# 搬遷測試操作手冊（A→B 真資料功能測試）

> 把公司 A 棧（舊 MSSQL VOC）真實資料轉進 B 棧（Schema B / PostgreSQL）測試庫，
> 用自己部門同事當申請人／簽核人，測 B 棧各功能。
> 相關程式：`scripts/export_mssql.py`、`scripts/migrate_a_to_b.py`、`migration/`、
> `scripts/run_dispatch_worker.py`。

## 一次性準備

1. **`.env` 確認（測試安全）**
   ```
   VOC_B_DB_URL=...            # 你的 PostgreSQL 連線字串
   TEST_MODE=True             # 所有信改寄到自己，不會真的發給名單
   TEST_DEV_EMAIL=你的信箱
   ```
2. **人員綁定**（填自己部門同事，email 直接寫；系統會自動反推 notes_id）
   ```bash
   cp scripts/migration_personnel.json.example scripts/migration_personnel.json
   # 廠棟工程師_申請人 / 環工負責人_簽核人
   ```

## 每次測試：把真資料灌進來

```bash
# A) 公司（能連 MSSQL）：匯出自己棟
python scripts/export_mssql.py --out export --plants K7      # 換成你的 plantno

# B) 能連 PG 的機器：轉換載入（沙盒/家裡皆可）
python scripts/migrate_a_to_b.py --export export --personnel scripts/migration_personnel.json --plants K7
#    → 會印出各表寫入筆數；搬遷冪等，重跑只更新不重複
```

> ⚠️ `VOC_dept` / `VOC_Curve` 兩張表舊專案沒留 ORM 可考，欄位名目前為假設值（已容錯多組 key）。
> 若這兩張沒進去，把 `export/VOC_dept.json` 一列的實際欄位名回報，即可校正對映。

## 啟動

```bash
python main_b.py                     # 網頁 → http://localhost:8000/home
python scripts/run_dispatch_worker.py  # 派報 worker（測異常派報＋那三頁時才需要，另開終端常駐）
```

> **搬遷測試不需要 `run_sync_worker`**——那支是 Kepware 即時同步用的；讀值已從 A 搬進來了。
> 只跑 `run_dispatch_worker` 即可。

## 功能測試對照表

| 測項 | 怎麼做 | 預期 |
|---|---|---|
| **儀表板燈號** | 開 `/home` | 各項目依真實讀值 vs 規格亮燈；被隔離的項目顯示「保養中」 |
| **異常派報（重點）** | 直接改 DB：把某個**未被隔離的水項目** `reading_current.value` 改到超過 `spec.oos_high`，等 worker 下一輪（或重啟 worker 立刻跑一輪） | 收到「【首發】」派報信（TEST_MODE 下寄到自己）；隔 15/30 分看有無升級信 |
| **隔離抑制派報** | 對某項目送隔離申請→簽核核准，再把它讀值改超標 | 該項目**不**派報（被隔離抑制），儀表板顯示保養中 |
| **異常查詢／回覆／報表** | 派報跑過至少一次後開這三頁（`/ui/history`、`/ui/reason`、`/report/ui`） | 出現剛才那筆派報紀錄（先前空是因為根本沒派報過） |
| **隔離送簽＋簽核** | 申請人身分申請→送簽（收到「待簽核」信）→切簽核人身分核准（收到「核准」信） | 兩封信都收得到 |
| **中水緊急通知** | `/warning/water_urgent/ui` | ⚠️ 固定查 `K14B` 廠（舊系統行為）；沒搬 K14B 資料會查無——要測需匯出時帶 K14B |
| **QA 手動輸入** | `/ui/qa` | 只列 `source_id=3(QA)` 的項目；棟內若無 QA 來源項目，清單本來就空（非 bug） |

## 提醒

- **改讀值改 `reading_current.value`**（`raw_text` 不用動），改完 worker 下一輪才派報；想立刻看就重啟 worker（啟動會馬上跑一輪）。
- **PG 若重啟**（沙盒／Docker 停過）要重跑 `bash scripts/dev_pg.sh` 並重新搬遷（本機開發叢集非持久）。
- **收不到信但 log 說寄了** = 正常，TEST_MODE 把信攔到 `TEST_DEV_EMAIL`；log 印的「原始收件人」才是正式環境會寄到的人。
- **派報 vs 其他通知的 rpttype 不同**：異常派報收件人是 `水/空 × Alert/OOS/OOC(含15/30)` 共 14 種 rpttype，與「水質異常」（中水通知）、「水保養中／空保養中」（隔離簽核）都不同；搬遷時 `build_personnel` 已一次種齊，不必手動補。

## 定時轉拋（長時間兩邊比對）

`scripts/migrate_a_to_b.py` 的 `run_migration` 是冪等的，把它掛計時器（cron／工作排程器）即可
當「定時轉拋 Job」長時間跑、兩邊比對。自動差異比對工具目前先不做（依先前討論）。
