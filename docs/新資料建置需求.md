## ⚠️ 2026-07-12 優化提案（**待使用者確認後才改寫下方表格規格**）

使用者提出「原本 tagname 對應 item 的設計可沿用，但需要優化」，主控盤點後提兩個具體建議：

### 提案一：tagname 收斂成單一真相來源
現況 `spec.tagname`（沿用舊系統的欄位）與 `tag_mapping.tagname`（B 棧新的同步驅動表）**兩處都存了 tag 名稱**，但同步 JOB 實際上只認 `tag_mapping`。`spec.tagname` 是舊資料帶過來的裝飾欄位，看起來有效但改了不會生效——將來一定有人踩。
**建議**：`tag_mapping` 為唯一權威，需求表只在一個地方要求填 tagname（下方第 3 張表的 tagname 欄移除，統一在第 4 張表填）。

### 提案二：四張表併成一張主表（大幅降低填寫負擔）
「廠區清單」與「量測項目清單」的內容**都能從「規格門檻」那張表推導出來**（每列本來就有 plantno 與 item）。
**建議改成**：
- **主表一張**：`plantno, item, unit, 類型, LAW, OOS, OOC, Alert, 允收, 來源, tagname, 排序`
  —— 一列 = 一個廠區的一個監測項目，把 tag 對應也併進來，環工部只填一張 Excel。
- **選填小表**：只在需要時填「廠區顯示排序/是否顯示」「項目顯示別名（pH1→pH）」。
- 載入器負責推導廠區/項目主檔、驗證、逐列回報錯誤。
**好處**：不會發生「項目清單有、規格表漏了」這種對不起來的狀況；填寫工作量從四張降為一張。

### 相關：日常維護改走網頁（已在實作）
一次性建置用 Excel 灌，**日常維護（新增廠棟/項目/tag 對應）改用網頁**——「基礎資料維護頁」已於 2026-07-12 發包實作（廠區/項目/Tag 對應三分頁），未來新廠棟上線環工部可自行建置，不必每次找工程師動資料庫。

## 你要提供的資料表（按優先順序）

### 1. 廠區清單（必要）
| 欄位 | 說明 | 範例 |
|---|---|---|
| plant_no | 廠區代號（唯一，各表用它關聯）| K7 |
| 顯示排序 | 儀表板由小到大排 | 1 |
| 是否顯示 | Y/N（預設 Y）| Y |

### 2. 量測項目清單（必要）
| 欄位 | 說明 | 範例 |
|---|---|---|
| item | 項目名（唯一；同名不同義請改名，如 VOC(M13)）| COD |
| 顯示名 | 儀表板顯示用，可空（空=同 item）| — |
| unit | 單位 | mg/L |
| 類型 | 水質 / 空汙 / 雨水溝（影響派報信分類：含"VOC"走空、其餘走水）| 水質 |

### 3. 規格門檻（必要，每廠區×項目一列）
| 欄位 | 說明 | 範例（單邊） | 範例（雙邊 pH/溫度） |
|---|---|---|---|
| plant_no / item | 對應上面兩表 | K7 / COD | K7 / pH |
| 法規值(LAW) | 純顯示文字 | 100 | 6-9 |
| OOS | 紅燈門檻；雙邊寫 low-high | 100 | 6-9 |
| OOC | 橙燈門檻 | 80 | 6.5-8.5 |
| Alert | 黃燈門檻，可空 | 60 | 6.8-8.2 |
| 允收值 | 超過亮黃燈，可空 | 80 | 6.5-8.5 |
| 資料來源 | SCADA / CWMS / QA（QA=人工輸入頁）| SCADA | SCADA |
| tagname | Kepware tag（來源=SCADA 才要）| K7.COD.PV | K7.PH.PV |
| 排序 | 廠區內顯示順序 | 2 | 1 |

「尚未建置」的項目：門檻欄留空即可（會顯示建置中）。

### 4. Kepware tag 對應（必要——第二階段轉拋 JOB 的驅動表）
| 欄位 | 說明 | 範例 |
|---|---|---|
| tagname | A 端（Kepware 轉拋庫）的 tag 名 | K7.COD.PV |
| plant_no / item | 對應到哪個廠區×項目 | K7 / COD |
| 寫入欄位 | 讀值 或 管制值欄（OOS上/OOC上/Alert上/OOS下/OOC下/Alert下）| 讀值 |

### 5. 人員與角色（必要——已有格式，沿用）
沿用 `scripts/migration_personnel.json`（empno / name / email 三欄，email 直接寫）：
- 廠棟工程師＝申請人；環工負責人＝簽核人。
- 派送名單（誰收派報信）若要與簽核人不同，另給一張：plant_no / rpttype類別(異常派報/中水通知) / empno / TO或CC。
  不給就預設「簽核人收全部」。

### 6. 部門（選填——部門權限頁用）
plant_no / dept_no 各一列。

### 7. 其他（選填）
- 歷史曲線連結：plant_no / item / URL（有才給）。
- K14B 中水：中水緊急通知頁寫死查 K14B——若要用這功能，上面 1~3 要包含 K14B 的資料。
