## 你要提供的資料表（按優先順序）

### 1. 廠區清單（必要）
| 欄位 | 說明 | 範例 |
|---|---|---|
| plant_no | 廠區代號（唯一，各表用它關聯）| K7 |
| 顯示排序 | 儀表板由小到大排 | 1 |
| 是否顯示 | Y/N（預設 Y）| Y |

### 2. 量測項目清單（必要）
| 欄位 | 說明 | 範例 |
|---|---|---|
| item | 項目名（唯一；同名不同義請改名，如 VOC(M13)）| COD |
| 顯示名 | 儀表板顯示用，可空（空=同 item）| — |
| unit | 單位 | mg/L |
| 類型 | 水質 / 空汙 / 雨水溝（影響派報信分類：含"VOC"走空、其餘走水）| 水質 |

### 3. 規格門檻（必要，每廠區×項目一列）
| 欄位 | 說明 | 範例（單邊） | 範例（雙邊 pH/溫度） |
|---|---|---|---|
| plant_no / item | 對應上面兩表 | K7 / COD | K7 / pH |
| 法規值(LAW) | 純顯示文字 | 100 | 6-9 |
| OOS | 紅燈門檻；雙邊寫 low-high | 100 | 6-9 |
| OOC | 橙燈門檻 | 80 | 6.5-8.5 |
| Alert | 黃燈門檻，可空 | 60 | 6.8-8.2 |
| 允收值 | 超過亮黃燈，可空 | 80 | 6.5-8.5 |
| 資料來源 | SCADA / CWMS / QA（QA=人工輸入頁）| SCADA | SCADA |
| tagname | Kepware tag（來源=SCADA 才要）| K7.COD.PV | K7.PH.PV |
| 排序 | 廠區內顯示順序 | 2 | 1 |

「尚未建置」的項目：門檻欄留空即可（會顯示建置中）。

### 4. Kepware tag 對應（必要——第二階段轉拋 JOB 的驅動表）
| 欄位 | 說明 | 範例 |
|---|---|---|
| tagname | A 端（Kepware 轉拋庫）的 tag 名 | K7.COD.PV |
| plant_no / item | 對應到哪個廠區×項目 | K7 / COD |
| 寫入欄位 | 讀值 或 管制值欄（OOS上/OOC上/Alert上/OOS下/OOC下/Alert下）| 讀值 |

### 5. 人員與角色（必要——已有格式，沿用）
沿用 `scripts/migration_personnel.json`（empno / name / email 三欄，email 直接寫）：
- 廠棟工程師＝申請人；環工負責人＝簽核人。
- 派送名單（誰收派報信）若要與簽核人不同，另給一張：plant_no / rpttype類別(異常派報/中水通知) / empno / TO或CC。
  不給就預設「簽核人收全部」。

### 6. 部門（選填——部門權限頁用）
plant_no / dept_no 各一列。

### 7. 其他（選填）
- 歷史曲線連結：plant_no / item / URL（有才給）。
- K14B 中水：中水緊急通知頁寫死查 K14B——若要用這功能，上面 1~3 要包含 K14B 的資料。
